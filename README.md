# IV-2-7 — Fork-Join Sorting Application

**Хичээл:** F.CSM302 Үйлдлийн систем · Бие даалт 1
**Хуваарилалтын код:** `IV-2-7`
**Сэдэв №7:** Fork-Join Sorting Application (сурах бичгийн Бүлэг 4, Programming Project 3)
**UI дүрслэл:** Recursion tree (рекурсийн мод)

Java-гийн **Fork/Join** параллель API ашиглан эрэмбэлэх хоёр алгоритмыг
(Mergesort, Quicksort) хэрэгжүүлж, рекурсив задралыг **интерактив модоор**
харуулна. Threshold, массивын хэмжээ, урсгалын тоо, өгөгдлийн хэв маягийг
UI-аас өөрчилж дахин турших боломжтой.

## UI-г 60 секундэд туршаад үзэх

1. `./run.sh` → цонх нээгдэнэ.
2. **Номын жишээ (Figure 4.27)** товчийг дарна → оролт `7, 12, 19, 3, 18, 4, 2, 6, 15, 8` болно.
3. `Threshold` = **2** болгоно.
4. **Ажиллуулах** дарна → 11 зангилаатай мод гарч ирнэ.
5. Дурын зангилаа дээр дарна → баруун талд тэр мужийн утгууд *өмнө / дараа* харагдана.
6. `Threshold`-ийг **5** болгоод дахин ажиллуулна → мод богиносно.
7. **Алхамчилсан горим** тэмдэглээд ажиллуулаад доорх гүйлгэгчийг чирнэ → мод алхам алхмаар ургана.

## Хэрэгжилтийн гол шийдлүүд

**`RecursiveAction`, `RecursiveTask` биш.** Эрэмбэлэлт нь массивыг газар дээр нь
өөрчилдөг, утга буцаадаггүй — сурах бичгийн заасан яг энэ шалтгаан.

**`invokeAll(left, right)`.** Энэ нь `left.fork(); right.compute(); left.join();`
-тэй дүйцнэ: нэг дэд ажлыг одоогийн урсгал өөрөө гүйцэтгэдэг тул дэмий fork
хийхгүй.

**Threshold.** Муж threshold-оос жижиг болмогц рекурс зогсож `insertionSort`
ажиллана. Threshold хэт жижиг бол fork-ийн зардал, хэт том бол insertion sort-ийн
$O(k^2)$ давамгайлна.

**Quicksort дээр гурван талт хуваалт.** Давхардсан утга их үед (`ALL_EQUAL`,
`FEW_UNIQUE`) энгийн хоёр талт хуваалт нэг тал руугаа бүрэн налж стек халдаг.
Гурван талт хуваалт ижил утгуудыг нэг алхамд эцсийн байранд нь суулгана —
`ALL_EQUAL` дээр мод **ганц зангилаа** болдог.

**Pivot-ыг хэш-ээр сонгоно.** Тогтмол байрлал (эхний / дунд / сүүлчийн) ашиглавал
эрэмбэлэгдсэн өгөгдөл дээр хуваалтын swap-ууд "эрэмбэлэгдсэн + хамгийн бага нь
төгсгөлд" гэсэн хэв маягийг үүсгэж, тэр нь түвшин бүрт давхарлан рекурсийн гүнийг
$O(n)$ болгодог. `(lo, hi)`-ээс гаргасан хэш нь өгөгдлийн байрлалтай хамааралгүй
тул энэ эвдрэлийг таслана, мөн үр дүн давтагдана.

## Синхрончлол (thread-safety)

ForkJoinPool-ийн олон worker урсгал `TraceRecorder`-ийг **нэгэн зэрэг** дууддаг
(`MergesortAction`, `QuicksortAction` бүр `open` / `close` дууддаг). Иймд модны
бүртгэл race condition үүсгэж, зангилаа алдагдуулах, дугаар давхардуулах ёсгүй.
Үүнийг `synchronized` ашиглахгүйгээр **цоожгүй (lock-free)** бүтцээр шийдсэн нь
сурах бичгийн Бүлэг 6–7 (синхрончлол)-ийн жишээ болно.

| Хуваалцдаг өгөгдөл | Ашигласан бүтэц | Яагаад |
|---|---|---|
| Зангилааны дугаар `nextId` | `AtomicInteger.getAndIncrement()` | "уншаад, нэмээд, бичих" гурван алхам нэг атомик (CAS) үйлдэл болно. Энгийн `int id++` бол read-modify-write тул хоёр урсгал ижил дугаар авч болно. |
| Зангилаануудын жагсаалт `nodes` | `ConcurrentLinkedQueue` | `ArrayList.add` олон урсгалаас дуудахад дотоод массив эвдэрч зангилаа алдагдана. `ConcurrentLinkedQueue` нь CAS дээр суурилсан lock-free дараалал. |
| `enabled`, `t0` | `final` талбар | Constructor-т нэг удаа онооно, дараа нь өөрчлөгдөхгүй. `final` талбар нь бүх урсгалд аюулгүй харагдана. |
| Нэг зангилааны талбарууд (`thread`, `forkNanos`, `before`, `after`) | Зөвхөн өөрийн урсгал бичнэ | Зангилааг `open`-оор үүсгэсэн урсгал өөрөө `close`-оор нөхдөг тул хоёр урсгал нэг зангилааг зэрэг бичдэггүй. |

**Уншилт ба happens-before.** Модыг уншдаг `snapshotNodes()`-ийг эрэмбэлэлт
**дууссаны дараа** дууддаг. `invokeAll` нь `join()` хийдэг тул дэд ажлуудын бүх бичилт
дуудагч урсгалд харагдана (Java Memory Model-ийн happens-before).
Иймд уншигч урсгал зангилааны талбаруудыг бүрэн, шинэчлэгдсэн хэлбэрээр хардаг.

**Тогтвортой дараалал.** Урсгалууд ямар дарааллаар ажиллахыг урьдчилан мэдэх
боломжгүй, тиймээс `nodes` дахь дараалал нь `id`-аар эрэмбэлэгдсэн байх баталгаагүй.
`snapshotNodes()` нь жагсаалтыг хуулж аваад `id`-аар эрэмбэлж буцаана. Ингэснээр UI
ижил оролт дээр үргэлж ижил, тогтвортой мод харуулна.

**Яагаад `synchronized` биш вэ?** `synchronized` блок нь бүх урсгалыг нэг цоожинд
дараалуулж параллелизмын ашгийг бууруулдаг. Бид эрэмбэлэлтийн хурдыг хэмждэг
(`Bench`), тиймээс бүртгэл нь эрэмбэлэлтийг аль болох удаашруулахгүй байх ёстой.
`--no-trace` горимд `open` нь шууд `null` буцаадаг тул бүртгэлийн зардал огт
гарахгүй.
